# 内存基线（P4：Debug 埋点 + 验收口径）

本文记录 PdxNext 桌面端（WinUI 3 / Windows App SDK / .NET 10）在 `fix/memory-cpu`
这一轮性能修复后的内存验收目标、实测方法与读数说明。埋点只在 **Debug** 构建里生效，
Release 构建既不写这行日志，也不调用 `Process`。

## 验收目标

| 场景 | 工作集目标 | 说明 |
| --- | --- | --- |
| 空载（启动完成，未进任何列表） | ≤ 250 MB | 主窗口 + 服务装配后的基线 |
| 工坊列表 30 条（滚一屏） | ≤ 450 MB | 封面按显示尺寸解码后的稳态 |
| 工坊详情页（滚一屏） | ≤ 550 MB | 详情正文 + 截图 + 描述图 |
| 翻译空闲 5 分钟后 | ≤ 350 MB | 本地翻译模型空闲卸载生效（默认常驻，可关 `KeepTranslationModelLoaded`） |
| 冷启动到主窗口可交互 | ≤ 2.5 s | 启动阶段不联网、不 await 大文件 IO |

目标看的是**工作集（WorkingSet64）**；托管堆与私有字节只作辅助判断，不单独设阈值。

## 实测方法

1. 用 Debug 构建启动：`dotnet build src/PdxLauncher.App -c Debug`，运行输出的
   `PdxLauncher.App.exe`，等主窗口出现后打开日志（设置页「打开日志」或
   `data\logs\` 下最新的 `*.log`），找到启动行：

   ```
   [启动完成] 内存：托管 … MB / 工作集 … MB / 私有 … MB；GC 0/1/2=…/…/…；工坊条目 … / 分页 … / mod 缩略图 …
   ```

   这一行就是**空载基线**。启动完成时封面预热（前 12 张）还在后台跑，等 5～10 秒再读一次日志缓冲。

2. 打开工坊列表，滚一屏（约 30 条），再打开任一工坊详情、滚一屏；然后关闭主窗口。
   关闭前会写一行 `[窗口关闭] 内存：…`，它是**本次会话的收尾读数**，用来对照列表 / 详情目标。
   若要观察单页峰值，可以在滚动结束后直接关窗，避免回退到别的页面把峰值冲掉。

3. 翻译空闲场景：开启本地离线翻译并翻译一次，随后静置 5 分钟不操作，再关窗看
   `[窗口关闭]` 的工作集；对照 350 MB 目标判断翻译模型是否真的被卸载。

> 读数受显卡驱动、DPI、窗口尺寸与背景图档位影响，同一台机器上比较趋势即可；
> 换机器时请把窗口尺寸（设置里保存的逻辑像素）一并记录。

## 已修的 4 个内存大头

1. **列表图按显示尺寸解码**：工坊 / 库列表封面不再按原图全尺寸解码，按卡片实际显示宽度解码
   （`ImageDecodeSize` / `ImagePixelSize`），单张位图从数十 MB 降到亚 MB 级。
2. **翻译模型空闲释放**：本地离线翻译模型约 1.22 GB，空闲后卸载；默认仍常驻（避免每次翻译重新加载），
   由设置项 `KeepTranslationModelLoaded` 控制，关掉后空闲 5 分钟回到 350 MB 以内。
3. **工坊缓存改真表**：工坊缓存从「整份 JSON + 内存字典」迁到 SQLite 真表
   （`workshop_items` / `workshop_pages`，schema v2），翻页不再把全量条目读进内存。
4. **封面 100 MB 磁盘配额**：`CoverDiskQuota` 给封面 / 截图目录设 100 MB 上限，超出按最旧写入时间清理，
   避免磁盘与「启动时扫描目录」的隐式内存一起膨胀。

## 怎么读日志

1. `[启动完成]` = 服务装配完成、主窗口刚创建时的快照，对应「空载」目标。
2. `[窗口关闭]` = 关闭流程落盘后的最后一次快照，对应「列表 / 详情 / 翻译空闲」目标；两次读数之间的差值就是本次会话的增量。
3. `内存：` 后的 MB 按 1 MB = 1024² B 换算并保留一位小数；`GC 0/1/2` 是三代回收次数，`工坊条目 / 分页 / mod 缩略图` 是**内存缓存条数**（不是磁盘文件数），用来判断缓存是否按预期分级。
